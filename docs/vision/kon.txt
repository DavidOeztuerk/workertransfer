Was ist "Presentation"?
Presentation ist einfach die Eintrittsschicht deiner Anwendung. Sie nimmt Requests entgegen und gibt Responses zurück.
Je nach Anwendung kann Presentation sein:
REST API (FastAPI)
GraphQL
gRPC
CLI
WebSocket
Background Worker
Message Consumer (RabbitMQ)
Scheduler
In Python würde das z.B. so aussehen:
Presentation
│
├── REST Controller
├── GraphQL
├── RabbitMQ Consumer
├── Cron Jobs
└── WebSocket
Alle rufen lediglich die Application-Layer auf.
Warum gibt es bei dir "API"?
Weil dein Projekt bisher nur eine HTTP-API besitzt.
Api
│
├── Controllers
├── Middleware
├── Dependency Injection
└── Swagger
Das ist deine Presentation-Schicht.
Was sind Contracts?
Das ist keine Clean-Architecture-Schicht.
Contracts existieren, damit mehrere Services dieselben DTOs oder Event-Definitionen verwenden können.
Zum Beispiel:
UserCreatedEvent

CreateUserRequest

UserResponse
Diese gehören weder zur Domain noch zur Application.
Sie sind lediglich Verträge zwischen zwei Prozessen.

Nächster Schritt
Wir beginnen nicht mit Code, sondern mit Kapitel 1: Die Plattform initialisieren.
Dort erstellen wir das komplette Monorepo mit uv, pnpm und Turborepo, richten die Workspace-Struktur ein und legen die Entwicklungsstandards fest. Danach bauen wir Schritt für Schritt zuerst die Shared Foundation, dann den Service-Generator und erst anschließend den ersten echten Microservice. So wächst WorkerTransfer auf einem stabilen Fundament statt auf kopiertem Boilerplate-Code.
